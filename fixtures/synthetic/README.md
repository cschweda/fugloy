# Synthetic fixtures

Generated by the test suite's writers (`packages/disasm/test/writers/`,
`packages/emu/test/unit/label-sample.js` for `label-file/`,
`packages/emu/test/unit/disk-samples.js` for `disk/`, and
`packages/emu/test/unit/model3-state-sample.js` for `emu/`) via `pnpm fixtures`.
Do not edit by hand: `packages/disasm/test/fixtures.test.ts`,
`packages/emu/test/unit/label-file.test.js`,
`packages/emu/test/unit/disk-image.test.js`, and
`packages/emu/test/unit/model1.test.js` fail if a committed file differs
from what the writer produces.

- `cmd/` — one .CMD load module per loader rule in the project plan.
- `bas/` — tokenized Level II BASIC programs saved from different base addresses.
- `label-file/` — a label and coverage file (`docs/label-format.md`) written by
  the emulator from a synthetic session; the disassembler's label-file tests
  read it.
- `disk/` — synthetic disk images, one per container shape the emulator reads
  (emu spec §5, "Disk images"): a 35-track single-density JV1, a mixed JV3,
  and DMKs in double density, doubled and single-byte single density, and
  mixed density. Made by the writers, nothing copied from a real disk.
- `emu/model3-state.json` — the end state (`serializeState`, the 64K as the
  CPU reads it, and the screen) of a synthetic-ROM Model III session, captured
  before emu phase 6 described the machine by model; the test `the Model III
  is unchanged` holds the Model III to it byte for byte. Rewrite it only for
  an intended change to the Model III.

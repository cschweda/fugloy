# Emu Phase 3 (Debugger, Coverage, Label File) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `m.debug` (breakpoints, watchpoints, trace, coverage, callers, snapshots, hooks) plus the §8 label file, and a disassembler that reads that file, so that a scripted emulator session produces a label file Fugløy's disassembler consumes (emu spec §11, phase 3).

**Architecture:** A `Debugger` object (`packages/emu/src/debug/debugger.js`) hangs off `Machine` as `m.debug`. `Machine.#beforeInstruction` asks it whether to stop (breakpoints) and tells it which instruction is about to run; `Machine` calls it again after each instruction (coverage targets, callers, trace, watch stops). Memory and port accesses are observed by swapping the CPU's `readMemory`/`writeMemory`/`readPort`/`writePort` for instrumented versions only while something listens, so an idle debugger costs one boolean test per instruction. The label file is plain JSON written by emu and read independently by `@fugloy/disasm` (TypeScript, no dependency on emu); `docs/label-format.md` is the contract and a committed fixture keeps both sides honest.

**Tech Stack:** plain JavaScript ESM (emu), TypeScript strict (disasm, cli), Vitest; `@fugloy/z80` stays an emu devDependency (tests only).

**Spec:** `docs/fugloy-emu-spec.md` §3 (API sketch), §7 (debugger), §8 and `docs/label-format.md` (file format), §10 (scripted-session test), §11 (phase 3 row). Phase 2's ledger deferred two items here: the breakpoint stop signal from `#beforeInstruction`, and clearing the key queue on restore.

## Rulings made while planning (the spec left these open)

1. **EXEC marks instruction starts.** `EXEC` is the first byte of an executed instruction (prefix included); `OPERAND` is its other bytes. Marking every M1 fetch as `EXEC` would make each `DD`/`CB` look like an instruction start to the disassembler. A lone prefix the CPU runs as its own step (spec §4) is a one-byte instruction.
2. **Fetches are not reads.** Instruction fetches never count as `READ` coverage, read watches, or `onMemRead`. A read is a fetch when it is among the instruction's first `len` reads and its address is `pc + k` for the k-th read. Lengths come from `instructionInfo` (Task 2), tested exhaustively against `@fugloy/z80`.
3. **`step` ignores breakpoints and watch stops;** only `run` stops on them. `step(n)` is an explicit instruction count.
4. **A run resumes past the breakpoint it stopped at:** the first instruction of every `run` is not checked against breakpoints, so `run()` after `reason: 'break'` makes progress.
5. **Trace entries carry no mnemonic.** `{ pc, bytes, cycles, regs? }`; formatting is the caller's (the MCP server formats with `@fugloy/disasm`). The sketch's `text` field is dropped from §3.
6. **Coverage and callers share one switch,** `m.debug.coverage.enable()`.
7. **The label file's coverage is keyed by `"0:0"`** as §8's prose requires (the §8 example is fixed to match), with six fields: `exec operand read write jump call`. **`rle-hex`** is comma-separated run lengths in uppercase hex, alternating zero-runs and one-runs, starting with a zero-run (which may be `0`), summing to 65,536 (an empty field is `"10000"`).
8. **Callers entries carry `count`** (how many times that edge was taken), so `observed` labels can cite it.
9. **Observed labels are call targets inside the loaded blocks,** named `SUB_hhhh`, evidence `called N× from M sites`. Disasm treats any name of its generated shape (`L`, `SUB_`, `DATA_`, `TBL_` + four hex digits) as "no name given": the address still becomes a root and the evidence a comment.
10. **A label file for another program is refused.** When the file's `program.sha256` is present and differs from the program's, disasm applies nothing and the CLI exits 2. (Hint files can match by content; a label file is keyed by address, so applying it to another program would state things that are not true.)
11. **Hint files win over label files** for names, comments, and overlapping overrides.

## Review Focus

1. Calling `run()` again right after it returned `reason: 'break'` must execute the breakpointed instruction and continue, not stop again at once (Task 1 test `resumes past the breakpoint it stopped at`).
2. A read watch over code must not fire on instruction fetches, while a write into code (self-modifying code, story 6) must (Task 3 test `fetches are not reads`).
3. A `restore` with keys still queued and sound recorded must leave neither behind, while the trace, hit log, and coverage survive (Task 5 test `restore clears the key queue and sound, keeps debugger state`).
4. `labelFile()` on a machine that never ran a loader (code poked in) must say it needs `name`, not write a nameless file (Task 6 test `needs a name when nothing was loaded`).
5. Disasm handed a label file whose `sha256` belongs to another program must refuse it rather than mark the wrong bytes as code (Task 7 test `refuses a file written for another program`; CLI exits 2).
